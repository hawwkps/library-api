# Style Guide — Library API

Правила проектирования этого API. Используются как ориентир при добавлении новых эндпоинтов.

1. **Версионирование в пути.** Все эндпоинты живут под `/v1/`. Несовместимые изменения выпускаются как `/v2/`, а не через версии в заголовках или query-параметрах.

2. **kebab-case в URL, snake_case в JSON, множественное число для ресурсов.** Пути через дефис (`/loans/{id}/return`), поля в JSON — через подчёркивание (`book_id`), ресурсы именуются во множественном числе (`/books`, а не `/book`).

3. **Действия, которые не вписываются в CRUD, — отдельным подресурсом-глаголом.** Возврат книги — это не `DELETE`, а `POST /loans/{id}/return`: это действие с побочным эффектом, а не удаление сущности.

4. **Неизвестные поля в запросе запрещены.** Все схемы объявлены с `additionalProperties: false`, чтобы клиент не мог случайно или намеренно прислать поле, которого нет в контракте.

5. **Сервер вычисляет производные поля.** Поля, которые зависят от других данных (`available_copies`), помечаются `readOnly` и игнорируются, если присланы в запросе.

6. **Единый формат ошибок.** Любая ошибка — это объект `ErrorResponse` с машинно-читаемым `code` (из фиксированного списка), `message` для человека и опциональными `details`.

7. **Пагинация — `limit`/`offset`.** Во всех списковых эндпоинтах единообразно: `limit` (по умолчанию 20, максимум 100), `offset` (по умолчанию 0).

8. **Фильтры — через query-параметры, без скрытой магии.** Например, `status=overdue` явно описан через `enum`, а не вычисляется по неявным комбинациям других полей.

9. **Идемпотентность для небезопасных операций создания с побочными эффектами.** `POST /loans` принимает `Idempotency-Key`, чтобы повторная отправка при сетевых сбоях не создавала дублирующиеся выдачи.

10. **Корректные коды ответа.** `201` — создание, `204` — удаление без тела, `404` — не найдено, `409` — конфликт состояния, `422` — валидация или нарушение бизнес-правила.
