# Саморевью — Library API

Проверка контракта `openapi.yaml` по стандартному чек-листу ревью API.

## Ресурсная модель

- [x] Ресурсы названы существительными во множественном числе (`/books`, `/readers`, `/loans`).
- [x] Иерархия вложенности минимальна и оправдана: `/loans/{id}/return` — единственное исключение из чистого CRUD, так как это действие, а не подресурс.
- [x] HTTP-методы соответствуют семантике: `GET` — чтение, `POST` — создание, `PUT` — обновление, `DELETE` — удаление.

## Контракты данных

- [x] Схемы запроса и ответа описаны явно через `components/schemas`, переиспользуются через `$ref`.
- [x] Поля, которые вычисляет сервер (`available_copies`, `id`, `loaned_at`, `returned_at`, `registered_at`), помечены `readOnly`.
- [x] Обязательные поля указаны через `required` отдельно для каждой схемы.
- [x] Неизвестные поля в запросе запрещены (`additionalProperties: false` на Book, Reader, Loan и теле `POST /loans`).
- [x] `returned_at` корректно описан как nullable через `type: [string, "null"]` (синтаксис OpenAPI 3.1 / JSON Schema).

## Ошибки

- [x] Единый формат ошибки (`ErrorResponse`) используется во всех ветках ответа с кодом ошибки.
- [x] Коды ошибок ограничены перечислимым списком (`enum`), а не произвольными строками.
- [x] Для каждого типа ошибки есть пример (`examples`) с реалистичным содержимым.

## Бизнес-правила

- [x] Лимит в 5 активных выдач и проверка `available_copies > 0` отражены как `422 BUSINESS_RULE_VIOLATION` с примерами.
- [x] Проверка `due_date` в будущем — через `422 VALIDATION_ERROR`.
- [x] Запрет удаления книги/читателя с активными выдачами — через `409 CONFLICT`.
- [x] Повторный возврат уже возвращённой книги — через `409 CONFLICT`.

## Идемпотентность

- [x] `Idempotency-Key` обязателен (`required: true`) на `POST /loans`.
- [x] Описан полный replay ответа при повторе с тем же ключом и телом.
- [x] Описан конфликт (`409 IDEMPOTENCY_MISMATCH`) при повторе с тем же ключом, но другим телом.
- [x] Описано поведение при конкурентных (одновременных) запросах с одним ключом.
- [x] Указан срок хранения ключа — 24 часа.

## Документация

- [x] У каждой операции есть `summary`.
- [x] Операции сгруппированы тегами `Books` / `Readers` / `Loans`.
- [x] Примеров больше трёх, включая как минимум один пример ошибки.

## Дополнительное задание

- [x] `Reader.full_name` помечено `deprecated: true` с описанием причины (переход на `first_name`/`last_name` в v2) — пример управления жизненным циклом поля в контракте.

## Что осознанно упрощено

- Аутентификация не описана в основном контракте (вынесена в опциональное дополнительное задание).
- Сортировка (`sort`) описана одним строковым параметром с конвенцией `-field` для обратного порядка, без отдельной схемы перечисления разрешённых полей — для файла такого объёма это избыточно.
- Конкретный способ хранения состояния идемпотентности (база данных, TTL-кеш и т.д.) не является частью контракта API и не отражается в OpenAPI-спецификации, только в описании ожидаемого поведения.
